# RandPass 密码生成器（2026-11-24）

## 1. 需求

用户要求：托盘右键菜单 + 面板 ☰ 功能菜单各加一个 **RandPass** 入口；面板标题栏 ☰ 左侧
增加**钥匙孔图标**作为一键主入口。三处打开同一个 RandPass 窗口，功能照 RandPass Lite 截图：

- 左栏参数：密码长度（默认 14）、密码数量（默认 14）、七个复选（小写/大写/数字/两位数字概率/
  无类似字符/自定义字符 默认全勾选，照截图；自定义格式默认关）+ 格式下拉（两个预设）
- 底部「生成密码」→ 右栏列出 N 条密码；**双击某条 = 复制到剪贴板**（用户确认加）
- **参数持久化**（用户确认做）：下次打开保持上次参数

## 2. 参数与默认值（= 截图状态）

| 参数 | 默认 | 说明 |
|---|---|---|
| 密码长度 L | 14 | 范围 4–64 |
| 密码数量 N | 14 | 范围 1–100 |
| 使用小写字母 | 开 | a–z |
| 使用大写字母 | 开 | A–Z |
| 使用数字 | 开 | 0–9 |
| 两位数字概率 | 开 | 见 §3 |
| 无类似字符 | 开 | 候选集剔除 `1 l I 3 L` |
| 使用自定义字符 | 开 | 文本框默认 `@#$`，字符并入候选集 |
| 使用自定义格式 | 关 | 预设两个，见 §4 |

## 3. 生成规则（纯函数，探针全覆盖）

1. **候选集** = 勾选的类（a-z / A-Z / 0-9 / 自定义字符去重并入）；「无类似字符」开时剔除
   `{1, l, I, 3, L}`。候选集为空（极端勾选组合）→ 回退全集（自定义字符除外）。
2. **随机源**：`RandomNumberGenerator`（密码学安全、AOT 安全、无反射）。
3. **两位数字概率**：逐槽生成内容；轮到数字类且本槽不是最后一槽时，以 **25%** 概率
   放一个"双同数字"（`11/22/…/00`，d 随机 0–9）并占掉 2 槽；否则普通 1 槽。
   内容总长恒 = L（双同数字消耗 2 槽，不是加长）。
4. **自定义格式**（§4）作用于内容（L 字符），`-` 为连接符不占 L。
   生成流程：先生成 L 位内容（规则 1–3），再按格式插横断行。

## 4. 自定义格式（用户口述规则 + 截图反推）

- 语法：数字 = 固定段长，`*` = 弹性段，段间以 `-` 连接；**内容总长恒等于密码长度 L**
  （用户原话："自定义格式的总长度受限于密码长度"），显示总长 = L + 段数 − 1。
- `*` 的分配：`rem = L − Σ固定段`，多个 `*` **平分 rem、余数给第一个 `*`**。
  L=14 时：`4-*-4` → [4,6,4]（与 RandPass Lite 截图 `GNKR-3jYwZj-5yg9` 逐段吻合）；
  `2-*-4-*-2` → [2,3,4,3,2]。
- 边界：`rem < 0` 时弹性段取 0 并整段（连同相邻 `-`）删除；段全删光 → 退化为无格式生成。
- 预设只有两个：**`4-*-4`**、**`2-*-4-*-2`**。第三个（`[8-4-4-4-12]`）**用户明确放弃，不实现**。

## 9. 跟进：左上角定死根因 + 位置记忆保留（同日）

用户报：三个入口（标题栏按钮/托盘行/☰菜单）打开 RandPass 都固定在屏幕左上角。
要求先改「永远居中」，随后明确：**能记住上次关闭的位置最好**。

### 根因（实测时间线 + 决定性实验）
- 活数据 ui-state `randPassWindow` 存了 `x:0, y:0`（21:47 用户关闭时写入）——首次打开（居中兜底路径）
  就落在 (0,0)，之后每次"恢复"都回到左上角，自我固化。
- 决定性实验（DialogProbe 真实平台窗口）：Show 前设 `Position=(100,100)`（**故意离中心**），
  Show 后实际位置 `(100,100)`，`WindowStartupLocation=Manual`（Avalonia 默认，无 CenterScreen 魔法）
  → **pre-Show Position 机制本身可靠**。第一版诊断用的值恰好等于屏幕中心，区分不了
  「显式生效」与「默认居中」，是诊断设计缺陷，已修正。
- 唯一能精确产出 (0,0) 的环节：`Resolve(Centre)` 对**退化工作区 (0,0,0,0)** 的钳位结果就是 (0,0)
  （已探针固化）。首次打开时 `WorkAreaAtCursor()` 返回退化矩形（RDP 会话瞬时状态，事后再现不出），
  居中算出 (0,0)，窗口打开在左上角，关闭时被记住。

### 修法（三层，全部有探针锁）
| 层 | 改动 |
|---|---|
| `PanelPlacement.AreaFor` | 永不返回退化工作区：指针区→主区→首区逐层过滤 `Degenerate`（Width/Height≤0）。纯函数 `Degenerate` 公开供探针。面板同享（同一 fallback 政策） |
| `RandPassWindow` | 新增 `IntendedGeometry`（Position+Size）：AppRuntime 放置后交给窗口，`OnOpened` 重断言——平台窗口此时已存在，set 就是活的 SetWindow，丢不掉。这是防"任何平台状态吞掉 pre-Show 位置"的兜底 |
| `AppRuntime.PlaceRandPassWindow` | **恢复完整几何**（尺寸+位置，校验：有限数、≥480×400、中心在某工作区内），无有效保存值才居中兜底；意向矩形经 `IntendedGeometry` 下发 |
| 活数据 | ui-state `randPassWindow` 的 x/y 重置为 null（清除卡死的 (0,0)，下次打开走居中，之后正常记忆） |

### 探针（DialogProbe 新 4 条 + 既有）
- `AreaFor` 不返回退化区（live）；`Resolve(Centre)` 对 (0,0,0,0) 区 == (0,0)（固化毒源）
- 显式 `(100,100)` Show 后实际 == `(100,100)`（离中心值，真实平台窗口）
- 居中兜底落点 == 计算中心（±1px）

## 9.1 更正：左上角真正的根因（同日，用户复测后定位）

§9 的"退化工作区"假设**被推翻**。用户复测：第一次居中（兜底路径），之后每次打开都 (0,0)。
活数据再次是 `x:0, y:0, width:580, height:540`——尺寸对、位置零。

### 决定性实验（DialogProbe，同一窗口三个时刻各读一次 Position）
窗口实际显示在 (100,100)（pre-Show 显式设置，probe 断言成立）：

| 时刻 | Position 读数 |
|---|---|
| Show 后（活着） | (100,100) |
| **Closing**（窗口销毁前） | **(100,100)** |
| **Closed**（产品原来在这里保存） | **(0,0)** ← 根因 |
| Closed 返回后 | (0,0) |

**Avalonia 在关闭序列里把 `Window.Position` 重置为 (0,0)**；`RememberRandPassGeometry` 原来
挂在 `Closed` 里 `CommitNow()`，每次关窗都把 (0,0) 存进 ui-state，下次打开忠实地"恢复"回左上角。
面板没有此 bug 的原因：它在 `Closing`（取消关闭+Hide，窗口仍活着）里 `RememberGeometry()`。

### 修法（commit 见下）
1. **活事件字段捕获**：`SizeChanged`/`PositionChanged`（窗口活着时）把真实几何写进
   `_randPassLivePosition`/`_randPassLiveSize` 字段；`PlaceRandPassWindow` 用意向值初始化字段。
2. **提交挪到 Closing**：`Closing` 里 `CommitNow()`（此时位置仍有效），`Closed` 只清理引用。
3. **关闭竞态防护**：`_randPassClosing` 标志——关闭序列自身的 Position 重置会触发
   PositionChanged，若不拦，事件处理器会把字段刷成 (0,0) 并再排一次防抖，400ms 后把 (0,0)
   写回文件，覆盖 Closing 的好值。
4. `RememberRandPassGeometry` 改写字段（永远不从窗口实例读几何）。

### 探针（DialogProbe 锁定三个时刻）
- `position read in CLOSING == (100,100)`（修复的保存点必须是活值）
- `position read in CLOSED == (0,0)`（固化原 bug 的平台行为，防止将来误以为 Closed 可读）
- `live events captured position/size`（PositionChanged×2、SizeChanged 期间字段为真值）
- §9 的 4 条放置断言保留（AreaFor 防退化降级为防御性保险，注释已更正）
